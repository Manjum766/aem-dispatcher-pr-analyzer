Fix "Waiting for status to be reported"

Branch protection required status check names must match exactly what GitHub Actions reports. This guide explains why it happens and how to fix it in 3 minutes.

Why does "Waiting for status to be reported" appear?

Root cause: GitHub branch protection requires a status check by name. The name stored in branch protection settings must exactly match the check name that GitHub Actions reports. There are two common mismatches:
What you configured in branch protectionWhat GitHub Actions actually reportsResult
Dispatcher Rules Lint AEM Dispatcher PR Analyzer / Dispatcher Rules Lint Waiting forever
SonarCloud Scan AEM Dispatcher PR Analyzer / SonarCloud Scan
+ SonarCloud App also posts:
SonarCloud Code Analysis		 Waiting forever
Snyk Scan AEM Dispatcher PR Analyzer / Snyk Scan Waiting forever
AEM Dispatcher PR Analyzer / Dispatcher Rules Lint AEM Dispatcher PR Analyzer / Dispatcher Rules Lint ✓ Matches

GitHub Actions status check names are always formatted as «workflow name» / «job name» — the workflow name: field at the top of the YAML, slash, the job name: field.

SonarCloud special case: The SonarCloud GitHub App also posts a separate check called SonarCloud Code Analysis. If you want that to block the merge too, add it as a fourth required check. But it is separate from the workflow job — you need both if you want both to gate the merge.

Step-by-step: configure branch protection

1

First, trigger a workflow run so GitHub has seen the check names.

Branch protection's search box only shows checks that have already run at least once. Push any commit to test-scan-PR (the commit 38cb906 you just pushed will trigger it). Wait for the Actions run to start — you don't need it to complete.

If you try to add the check name before the workflow has ever run, GitHub shows "no results" in the search box. The commit was just pushed — wait ~30 seconds for the run to appear in Actions.
2

Open branch protection settings

Navigate to:

Find the rule for master (or main) and click Edit. If no rule exists, click Add branch protection rule and set the branch name pattern to master.

Troubleshooting

SymptomCauseFix
Check name doesn't appear in search box Workflow has never run on this repo / branch Push any commit to trigger a run first, then re-open branch protection settings
Still shows "Waiting" after adding correct names Old incorrect check name is still listed Delete the old check name entry in branch protection and add the correct AEM Dispatcher PR Analyzer / … one
SonarCloud shows "Waiting" even though workflow passed Two different checks: workflow job vs SonarCloud GitHub App Use AEM Dispatcher PR Analyzer / SonarCloud Scan for the workflow job; add SonarCloud Code Analysis separately for the App check
Checks pass but merge button still locked "Do not allow bypassing" is off, or a different required check is still failing Check the full list of required checks in branch protection — there may be an old entry still listed
Workflow is cancelled mid-run Concurrency group cancels previous run when new commit pushed Expected behaviour — the new run takes over. Only the latest push matters.

How GitHub status check names are formed

# Workflow file
name: AEM Dispatcher PR Analyzer   ← part 1 of the check name

jobs:
  dispatcher-lint:
    name: Dispatcher Rules Lint     ← part 2 of the check name

# GitHub reports this check as:
# "AEM Dispatcher PR Analyzer / Dispatcher Rules Lint"

The job id (dispatcher-lint:) is never used in the check name — only the name: field is. If a job has no name:, GitHub falls back to the job id.

Quick verify: After the next workflow run completes, go to the PR → Checks tab → click any check → the URL will show the exact check name GitHub registered. That's what branch protection needs to match.
